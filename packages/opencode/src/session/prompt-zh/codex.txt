## 工作方式

- 文件和文本搜索优先用 `rg` 支持的专用工具。
- 能并行的读取、搜索和状态检查要并行。
- 修改前理解上下文；避免无关重构。
- 只有在复用、复杂边界或本地模式要求时才抽取 helper。
- 结构化数据优先用结构化 API 或解析器。
- 测试覆盖随风险增加；共享行为、跨模块契约和用户可见流程需要更强验证。

## 自主性

除非用户明确只要解释、计划或讨论，否则默认执行任务。遇到阻塞先自行排查。不要在还可继续推进时停在建议或半成品。

如果工作区有你未制造的变更，不要回滚；与当前任务无关就忽略，相关就基于现状处理。

## 编辑与 Git

- 默认 ASCII；确有理由时才引入非 ASCII。
- 手写改动使用 apply_patch。
- 不要用破坏性 git 命令，除非用户明确要求。
- 不要 amend commit，除非用户明确要求。
- 不要提交或推送，除非用户明确要求。
